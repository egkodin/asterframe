# Frontend specialist map

This is a concern index, not an instruction to load every skill. Resolve names from the current session's available-skills catalog, including plugin-qualified names. Read the matching installed `SKILL.md` and only the references needed for the task. Do not assume a cached plugin directory is active. A missing optional specialist falls back to Asterframe's bundled guidance; a missing tool is a reported capability gap.

Asterframe is the explicitly chosen workflow here. Impeccable remains the default elsewhere. A specialist supplies evidence or a bounded capability; it does not start a second design workflow. Respect explicit-only invocation policies. Never silently install tools, add a second component system, generate paid assets, publish private code, or expand a component fix into a site rebuild.

## Brand, tokens, and component families

|---|---|---|

| `generate-ui-from-brand` | Translate an actual brand source into UI structure | Reuse existing DESIGN/tokens first; preserve source provenance instead of inventing a brand |
| `brand-visual-language` | Shape, type, icon, and material consistency | Preserve brand commitments; standard semantic icons beat decorative substitutes |
| `algorithmic-color-palette` | Derive missing palettes and semantic roles from brand colors | Check contrast in actual states; near-black/off-white are options, not universal replacements |
| `color-mode-and-theme` | Light, dark, or both based on usage and product commitments | Check all existing themes; do not create a theme switcher or second theme without a need |
| `modular-scale-typography` | Display/body/utility hierarchy, rhythm, and measure | Use platform-readable roles and real long copy; a pixel font size alone does not prove WCAG compliance |
| `component-family-consistency` | Shared control anatomy, sizes, and state language | Reuse tokens and primitives; component roles may differ while their family stays coherent |
| `elevation-and-depth` | Communicate layer and interaction hierarchy | Use border/shadow/material only when useful; neither mandatory border-plus-shadow nor a blanket ban is valid |
| `real-world-metaphors` | Familiar affordances where they clarify a task | Match the user's concepts; a literal physical metaphor must not obscure a digital operation |

## Layout, hierarchy, and expert workflows

| `layout-paradigms-and-consistency` | Table, feed, master/detail, board, or narrative | Choose from the user's task and content; do not make every page a card grid |
| `visual-emphasis-and-hierarchy` | Primary action and reading order within each task group | Contrast and proportion establish priority; avoid competing primary actions |
| `repeated-component-alignment` | Shared slots and anchors in rows/cards | Test unequal real content; reserve useful slots without hiding information |
| `ui-density` | Density for expertise, frequency, and input device | Dense expert desktop tools and spacious marketing can both be correct |
| `operational-expert-tool-ui` | Repeated precision work, keyboard speed, hierarchical data | Protect table scanability and workspace; touch requirements apply to actual touch usage |
| `domain-expert-configuration` | Persistent defaults versus per-run parameters | Use domain vocabulary, show override scope, preserve settings and drafts |
| `coordinated-data-views` | Linked table/map/chart representations | Share filters and selection when both views help; use a switch on constrained screens when appropriate |
| `data-display-and-selection` | View modes, selection, bulk actions | Separate row selection from nested controls; expose selected count, action scope, and keyboard behavior |

## Forms, overlays, states, and recovery

| Source skill | Decision to make | Quality gate |
|---|---|---|
| `button-states` | Rest, hover, press, focus, disabled, pending | Stable target geometry and understandable state; CSS pointer blocking alone is not a keyboard or duplicate-submit guard |
| `form-design` | Labels, helper text, validation, and submission | Keep labels visible; associate errors and explain blocked actions; do not blindly disable submission without useful feedback |
| `modal-and-overlay-patterns` | Tooltip, popover, drawer, sheet, or modal | Choose the least interruptive surface; correct Escape, focus restoration, and modal-only trapping |
| `loading-states-and-perceived-performance` | Spinner, skeleton, progress, optimistic UI | Preserve useful data and layout; optimism requires a recoverable operation, not a fabricated success |
| `notifications-and-recovery` | Inline error, transient status, persistent banner, retry/undo | Recovery must be actionable and supported by the actual operation; critical errors cannot vanish in a toast |
| `status-colors-and-errors` | Semantic state vocabulary and error severity | Pair color with text/icon semantics; distinguish warning, failure, pending, and success |

## Accessibility, responsive behavior, and performance

| Source skill | Decision to make | Quality gate |
|---|---|---|
| `wcag-accessibility` | Applicable accessibility criteria and test paths | Check semantics, names, focus, contrast, non-color meaning, keyboard, zoom, motion; no blanket legal or compliance claims |
| `antislop-human`, `antislop-layoutmobile` | Measured contrast, keyboard/state visibility, content-driven reflow, and mobile keyboard/fixed-bar problems | Use applicable criteria and intermediate widths; correct large-text units and unrounded ratios, not blanket overflow or 44px compliance claims |
| `semantic-html-and-seo` | Native elements, document structure, metadata, enhancement | Scope SEO to relevant pages; meaningful alt text or decorative treatment; preserve behavior without unnecessary ARIA |
| `responsive-paradigms` | Mobile touch, tablet, desktop, and input changes | Recompose hierarchy; verify safe areas, long copy, real gestures where possible; a resized viewport proves layout only |
| `scroll-areas` | Page versus local scrolling | Avoid unnecessary nesting; deliberate wide data regions stay accessible without discarding columns/data |
| `sticky-and-fixed-elements` | Persistent controls and context | Prevent obscured content/focus with zoom, virtual keyboards, safe areas, and dynamic viewport changes |
| `performance-and-web-vitals` | Diagnose load, layout stability, and interaction cost | Measure relevant paths; separate lab and field evidence; optimize the actual bottleneck, not a guessed score |

Prefer semantic HTML, native controls, CSS, and existing accessible primitives before custom behavior. Comfortable 44px touch targets, density presets, and typography scales are design starting points; test applicable WCAG criteria and exceptions independently. Browser screenshots and automated checks do not establish complete accessibility or legal compliance.

## Motion

| Source skill | Use for | Gate |
|---|---|---|
| `find-animation-opportunities` | Read-only motion scouting | Report accepted and rejected candidates with purpose, timing, easing, and properties; do not implement in scout mode |
| `micro-interactions` | Immediate feedback and small state changes | Keep targets stable, feedback non-blocking, and repeated actions quiet |
| `motion-and-storytelling` | Spatial explanation and rare storytelling moments | Motion earns attention by improving comprehension; no universal reveal or cinematic requirement |
| `apple-design` | Pointer continuity, interruptible springs, sheets/drag | Never lock input during a transition; preserve velocity where appropriate and provide reduced-motion behavior |

Animated icons/illustrations follow the same frequency and attention budget. Prefer CSS for simple effects and an already-installed motion library when it genuinely fits. A video-composition GSAP reference does not require GSAP in the product.

Icons8 and Ouch share `icons8.json` version 2. Each preserves the other's section, `tokens`, and unknown values. Read/migrate older locks without data loss; preserve a legacy `ouch.json` and report its replacement when migrated. If locks disagree, resolve the conflict before switching a family. Account authorization, free flags, preview availability, and publication rights are different facts: verify the selected asset's actual entitlement and required attribution. Do not silently buy a format or persist secrets in asset locks.

| `code-review` | Requested review or review of changed behavior | Findings need evidence and impact; do not edit in read-only review scope |
| `antislop-code` | Meaningful comments in touched code or a comment-only cleanup | Preserve constraints, security/API/legal context; no arbitrary length cap or executable changes in a comment-only task |
| `tdd` | Explicit test-first work | Respect the requested loop; otherwise add meaningful regression checks only where useful |
| `setup-pre-commit` | Requested repository hook setup | Existing checks can be run without installing hooks or changing contributor workflow |
| `penetration-testing-with-strix`, `managed-pentesting-with-strix`, `fix-security-vulnerabilities-with-strix`, `ci-security-scanning-with-strix` | An authorized security test, confirmed vulnerability, or requested CI security integration | These are separate security tasks with their own target/account/data boundaries, not automatic UI QA |

Run the project-required checks and applicable production build for implemented frontend work. Verify the actual critical flow and relevant states in the available browser; use Obscura here and respect tool restrictions. Fix failures and repeat affected checks; stop once acceptance criteria pass. Clearly distinguish source checks, browser rendering, keyboard/touch/device behavior, automated accessibility results, field performance, and deployment. Never report unavailable or unexecuted checks as passing.
